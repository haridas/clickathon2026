01 · The problem

Ad revenue anomalies are high-cardinality, high-velocity, and easy to miss

01
9 independent dimensions, millions of events a day. A fault scoped to one OS on four countries doesn't move any dashboard total enough to notice.
02

03
Dimension tables get regenerated between data drops. The same device ID can carry a different country or category next week — a naive detector silently misattributes segments and raises false incidents.

04 · ClickHouse, used end to end

One engine, four jobs

Dictionaries — COMPLEX_KEY_HASHED
O(1) segment lookups inside every materialized view. No per-query JOIN plan against a dimension table sized in the thousands of rows.
Materialized views that fire on INSERT
An alert can exist in the same transaction as the event that caused it — the alerting layer has no separate schedule to fall behind.
SummingMergeTree + ARRAY JOIN — marginal, not cubed
One row per (dimension, value, hour), built from a literal array of 9 dimension tuples: 61,440 rows, versus the 7.9M-row full cube the naive approach produces for the same facts.
Parameterized views — rca_scan / rca_seg / rca_volume
The drill-down protocol as a callable query with named arguments, not a one-off script re-written for every incident.
Cross-database, read-only baselines
A fresh dataset is scored against a trained baseline in another database without ever writing to the source — the June data stays untouched.
05 · LibreChat integration

A conversational analyst on top of the same tables

The agent's entire context is one file: a system prompt that teaches it the table catalog, the four-step drill-down protocol, and the traps that produce a confident wrong answer if skipped.

Every SQL example inside it was executed against the live cluster before it shipped — the agent is never reasoning from a description of the schema, it's reasoning from queries that were proven to run.
